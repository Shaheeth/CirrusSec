# Interview Prep

Answers are deliberately plain — put them in your own words after reading the code.

## Explanations

**30 seconds:** I built a cloud security analyser. It reads a simulated AWS environment, applies ten deterministic rules to find misconfigurations, scores the risk, builds a graph of how resources connect to find potential attack paths, and analyses CloudTrail-style logs. An AI layer explains the results using only verified findings and a small knowledge base, and it generates a dashboard and PDF report.

**1 minute:** (above) + The key design choice is that rules, not the LLM, detect problems. The model can only explain, so it can't invent findings. I separate FACT, AI interpretation and recommendations, and I added guardrails against prompt injection, invented resources and destructive advice. I tested these with 56 automated tests.

**3 minutes:** (above) + Walk the NovaTech demo: public web server → SSH open → role with `s3:*` → unencrypted customer bucket; show risk breakdown, attack path, activity alerts, ask the AI which fix to do first, generate the report. Close with limitations: simulated data, simplified IAM evaluation, TF-IDF retrieval, no real AWS yet.

## Basic
1. What is cloud security / CSPM? 2. What is least privilege? 3. What is a security group? 4. What does CloudTrail record? 5. What is an IAM role vs user?

*Sample answer (CSPM):* "Continuously checking cloud configuration against best practice — for example public buckets or open SSH — and prioritising what to fix. It tells you about weaknesses, not whether someone is attacking right now."

## Technical
1. How does your rule engine work? 2. How do you find attack paths? (graph + path search from internet to sensitive targets) 3. How is the risk score computed? 4. What does the RAG pipeline do? 5. How do you parse untrusted JSON safely?

## Security
1. Why is SSH on 0.0.0.0/0 risky? 2. Why are wildcard IAM policies dangerous? 3. What is a prompt-injection risk in your app and how is it mitigated? 4. Why would an attacker stop CloudTrail? 5. What makes a public bucket "critical" vs "high"?

## Architecture
1. Why separate detection from AI? 2. Why SQLite and when would you change it? 3. How would you add a new rule? (register a `Rule` + tests) 4. How would you add real AWS collection safely? (read-only role, sandbox account, cost limits, same `Resource` model) 5. How would you scale scanning?

## AI
1. What is RAG and why use it? 2. How do you prevent hallucinated resources? (facts by code, ID verification in output) 3. What can go wrong with retrieval? 4. Why a local model? 5. How do you evaluate answer quality? (grounding checks, unit tests with a malicious fake LLM)

## Project-specific
1. Walk through the NovaTech attack path. 2. Why is `customer-backups` risk 100 but `web-sg` 75? 3. What does your tool miss? 4. How do you avoid claiming an attack happened? 5. What would you build next?

*Sample answer (what it misses):* "IAM conditions, permission boundaries and SCPs; real network routing; vulnerabilities in the software on instances; and any statistical baseline for anomalies. Attack paths are potential, based on configuration only."
